# Applicability

This contract fits one bounded live proof. Two original Unreal domains propose QA and QB for shared_slot_01. Python resolves one fixed batch and commits one R1. Both original domains must then display R1 owner domain_A. The complete terms remain in CONTRACT_LAWS.md.

## Good fit

Use it to prove that physical proposals return through canonical arbitration into both living representations. Keep domain_A, domain_B, QA, QB, R0 and R1 fixed. Keep Python as the canonical mutation owner. Preserve the original processes and all predecessor bytes.

## Bad fit

Do not use this candidate for networking, open-ended collection, autonomous batch members, new input classes, physical movement, multiple subjects, streaming, randomness, retries, re-admission, recovery, production scale or trusted CI. Those exclusions remain binding.

## Failure conditions

Missing or altered dependencies reject. A stale process binding, wrong call order, invalid schema, missing artifact, altered canonical record or false raw-world observation rejects. Run every one of the 21 failure programs and six canonical faults exactly as frozen. Do not replace a physical failure with a summary flag.

An IPC timeout at 60 seconds ends the witness without changing membership. Each live case is capped at 900 seconds. Preserve failure evidence. A failure grants no retry, recovery or replacement authority beyond the declared replacement-process negative.

## Boundaries

The candidate costs one successful build and 35 paired cases. It uses 70 original process launches and one replacement-process negative. It must produce 219 fresh runtime artifacts and a 289-member release. Total wall time remains unmeasured.

MCDP verifies the intermediate implementation contract. P16 may seal only implementation_contract_sealed. Phoenix must still produce the unchanged live acceptance proof. Game Phase 4 remains sealed. Game Phase 5 has a frozen specification. No new live acceptance, game seal or trusted CI is claimed here.

Replace this contract only through a versioned successor. Keep the current frozen acceptance intact until that successor is approved. Do not silently broaden this candidate.
